# Сообщения об ошибках

Лаунчер 0.4.0 открывает форму кнопкой «Сообщить об ошибке». После аварийного завершения
запущенной им игры он предлагает заполнить эту же форму. Отправка начинается по кнопке
пользователя. Заголовок, категория, шаги, ожидаемый и полученный результат дополняются
версией лаунчера и движка, хешем исходников движка, ОС и доступными сведениями о GPU.
Последний фрагмент engine.log ограничен 24 КБ; его можно исключить и просмотреть до отправки.
Пути к домашнему каталогу, OpenSC, Data и overrides заменяются обозначениями.
Оригинальные игровые архивы и изображения автоматически не отправляются.

Неотправленное обращение находится в `OPENSC_HOME/reports/outbox/`. При повторной отправке
сохраняется идентификатор запроса. Квитанции с номерами `OSC-…` остаются в `reports/receipts/`.
Форма восстанавливает ожидающее отправки обращение при следующем открытии лаунчера.

## Сервер

При заданном `OPENSC_REPORT_DB=/srv/reports/bugs.sqlite3` сервер включает
`POST /api/v1/bug-reports`. Тот же HTTPS-домен используется для игры и обращений.
SQLite хранится в отдельном постоянном томе вне каталога сайта. WAL, транзакции и
синхронная запись сохраняют связь обращения с квитанцией. Схема содержит tickets,
submissions, status_history и schema_migrations.

Повтор одного request_id возвращает прежний номер; изменённые данные с тем же ID
отклоняются. Похожие обращения одной версии группируются с подсчётом повторов.
Публичного просмотра обращений нет. Администрирование выполняется через SSH:

```sh
docker exec opensc_web /opensc-web --reports list
docker exec opensc_web /opensc-web --reports show OSC-012345ABCDEF
docker exec opensc_web /opensc-web --reports status OSC-012345ABCDEF triaged "Воспроизведено"
docker exec opensc_web /opensc-web --reports status OSC-012345ABCDEF in_progress "Исправляется"
docker exec opensc_web /opensc-web --reports status OSC-012345ABCDEF fixed "Исправлено в выпуске"
docker exec opensc_web /opensc-web --reports backup /srv/reports/backups/manual-unique.sqlite3
```

Состояния: new, triaged, in_progress, fixed, closed. Изменения записываются в историю.
Вывод show ограничен 50 последними экземплярами, list — 200 последними карточками.

Общий JSON ограничен 64 КБ, параллельные операции — восемью, приём с одного IP —
шестью запросами в минуту с начальным запасом три. IPv6 группируется по /64.
Квота первой версии — 10 000 экземпляров; при заполнении возвращается ошибка,
а локальная копия сохраняется. IP не записывается в SQLite. Действуют прежние
проверки доверенного прокси, ограничения загрузок и блокировка сканеров.

Для ежедневного снимка предусмотрены server/backup-reports.sh и systemd service/timer.
Таймер запускается после установки на сервер; копии остаются в приватном томе.
Резервные копии создавайте командой backup: она учитывает WAL. Копировать только
основной файл работающей базы через cp недостаточно. Восстановление: остановить
сервис, сохранить текущую базу вместе с WAL/SHM, установить проверенный снимок и
вновь запустить сервис с прежними правами тома. Конкретный развёрнутый путь,
образ и проверенные команды отката записываются в отчёт выпуска.

Это первая система обработки обращений: вложения, публичный кабинет, обратная связь
по электронной почте и автоматическая отправка отчётов о сбоях в неё не входят.
