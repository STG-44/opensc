# Игра в OpenSC

22 октября 2026 опубликованы лаунчер **0.3.0** и игра **0.1.0-test.20261022.1** на [shadow-test.zaikinagroup.ru](https://shadow-test.zaikinagroup.ru/). [Пять сборок движка](https://github.com/STG-44/opensc/actions/runs/39737589793) и [четыре сборки лаунчера с проверкой установщиков](https://github.com/STG-44/opensc/actions/runs/39740079322) прошли CI.

Установка по доверенному HTTPS, выбор семи Linux-файлов из манифеста на 35 файлов, проверка SHA-256, запуск из лаунчера и отрисовка обучения проверены на CachyOS. Локально прошли 528 тестов движка, 12 тестов лаунчера и 5 проверок публикации. Окна Windows/macOS и Linux ARM64 ещё требуют ручного тестирования.

Лаунчер, движок и сервер находятся в одном репозитории, но собираются независимо:

| Каталог | Назначение |
|---|---|
| `src/` | Нативный лаунчер 0.3.0, egui |
| `engine/` | Текущий движок Shadow Company, Rust 1.99.0 / Bevy 0.20.0 |
| `server/` | Уже работающая раздача обновлений, Rust/Axum |

Папка `engine/` содержит весь текущий код игры и учебные документы. Оригинальные
данные остаются в выбранной пользователем установке. Их нет в исходниках и пакетах.
Текущий игровой этап — меню, видео и обучение с оригинальным нижним HUD;
полная кампания и оставшиеся механики требуют дальнейшей разработки.

## Запуск и пользовательские файлы

Лаунчер запускает `shadow-game` отдельным процессом, без командной оболочки:

```text
--game-dir <абсолютный путь к оригиналу или Data>
--settings <OPENSC_HOME>/game/settings.json
--overrides <выбранная папка улучшений или OPENSC_HOME/overrides>
```

`game/`, `overrides/`, `config.json` и `engine.log` лежат вне `versions/` и
сохраняются при установке новой версии. Существующие настройки лаунчера 0.2.0
читаются с новыми значениями по умолчанию. У старого лаунчера остаётся рабочим
контракт `--data`: игра принимает его как синоним `--game-dir`.

Лаунчер автоматически проверяет обновления при запуске и устанавливает новую
доступную сборку. В настройках это можно отключить. Уже установленный выпуск
с тем же отпечатком повторно не скачивается. При ошибке сети или отмене прежняя
активная версия сохраняется. Папки прошлых версий остаются на диске.

Без графического окна лаунчера можно проверить установку и запустить игру:

```sh
opensc-launcher --check
opensc-launcher --install
opensc-launcher --verify
opensc-launcher --launch "/путь/к/Shadow Company"
```

## Сборка

Лаунчер: `cargo test --locked` и `cargo build --release --locked` из корня.
Движок: из `engine/` выполнить:

```sh
cargo test --workspace --locked
cargo build --release --locked -p shadow-model-viewer --bin shadow-game
cargo metadata --locked --format-version 1 --filter-platform x86_64-unknown-linux-gnu > metadata.json
python3 scripts/package-game.py --binary target/release/shadow-game --cargo-metadata metadata.json --target x86_64-unknown-linux-gnu --profile release --build-id 0.1.0-test.20261022.1 --strip-tool strip --output dist/payload
```

На Windows имя файла — `shadow-game.exe`; в `--target` указывается соответствующий
Rust target. Утилита проверяет заголовок бинарника и архитектуру. `--strip-tool`
применяется к отдельной копии, а не к файлу в кэше Cargo. При готовой stripped
release-сборке этот аргумент не требуется. Упаковщик использует Python 3.11+;
на компьютере игрока Python и Rust не нужны.

Workflow `.github/workflows/engine.yml` готовит пакеты Linux x86_64/ARM64,
Windows x86_64 и macOS Intel/Apple Silicon. Запуск CI сам по себе не подтверждает
работу окна и драйверов на всех ОС. Нативная проверка игры пока выполнялась на CachyOS.

Linux-сборка с текущей CachyOS требует glibc 2.44 и подходит для локальных
проверок. Опубликованный движок собран на Ubuntu 22.04 и требует glibc 2.35. Лаунчер собран на Ubuntu 24.04 и требует glibc 2.39. Для отдельной локальной сборки подготовлен `packaging/engine/Dockerfile.linux` на Debian 12. Фактическое требование
glibc записывается в `build-info.json`. GNU-архив не подтверждает поддержку musl
или всех старых дистрибутивов; отдельный Flatpak остаётся следующим этапом.

## Подготовка обновления

Из корня репозитория:

```sh
python3 scripts/publish_release.py --version 0.1.0-test.20261022.1 --package linux-x86_64=engine/dist/payload --notes "Тестовая сборка: меню и обучение" --output dist/updates
```

Для остальных платформ повторить `--package`. Не добавлять запись для ОС,
если её настоящий бинарник ещё не собран. Используется прежний формат
`manifest-v1.json`: платформы `linux-x86_64`, `windows-x86_64`, `macos-x86_64`,
`macos-aarch64`, `linux-aarch64`, с отдельными файлами и SHA-256.
`data_directory` остаётся `null`: оригинал берётся у игрока.

Новый выпуск сначала проверяется по отдельному манифесту. Файлы загружаются
в неизменяемый `updates/releases/<version>/`, затем проверяются через HTTPS.
Только после проверки атомарно заменяется `updates/manifest-v1.json`.
Прежний манифест сохраняется вне публичного каталога; его атомарное восстановление
возвращает предыдущий выпуск. Traefik и сервисы других доменов для выпуска игры
менять не требуется. Контрольные суммы работают вместе с доверенным HTTPS;
отдельная криптографическая подпись манифеста в лаунчере пока не реализована.
