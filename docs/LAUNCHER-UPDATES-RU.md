# Обновления лаунчера 0.4.0

Игра проверяется при открытии окна и каждые 60 секунд. При включённой автозагрузке
найденный выпуск устанавливается автоматически. Запущенная игра откладывает установку
до завершения процесса. Неизменившийся манифест не вызывает повторной загрузки.
Остановленная или повреждённая загрузка ждёт явного повтора. HTTP 429/503 с коротким
Retry-After обрабатывается с ограниченным числом повторов и возможностью отмены.

Сам лаунчер проверяется отдельно после текущей операции с игрой и затем раз в час.
В настройках есть отдельный переключатель его автоматического обновления.
Новая версия открывается, когда игра завершена, закрыты настройки и форма обращения.
Текущее окно закрывается после подтверждения нового окна; при ошибке остаётся открытым.

Лаунчер 0.3.0 такого механизма не содержит. Переход на 0.4.0 требует одной установки
нового пакета. Следующие выпуски 0.4.0 уже сможет получать сам.

## Формат и доверие

`/updates/launcher-v1.json` — атомарно заменяемый конверт с schema_version, payload
и signature. Payload — точный UTF-8 JSON обычного манифеста. Ed25519 подписывает
`OPENSC-LAUNCHER-UPDATE-V1\n` и эти байты. В клиент встроен открытый ключ из
`src/launcher-update-key.bin`; ключ проверки с сервера не загружается.
После проверки подписи проверяются пути, платформа, размеры и SHA-256 файлов.

Каждая платформа содержит нативный файл и THIRD-PARTY-NOTICES.txt. Подготовленные
версии находятся в `OPENSC_HOME/launcher-update/versions/`, отдельно от первоначальной
установки и каталога игры. Системные каталоги пакетов и исходный установленный файл
сохраняются. Новое приложение получает тот же OPENSC_HOME. Переход использует временный
локальный токен готовности окна. Понижения версии и автоматического запуска обновлений
с неподходящей подписью нет.

Эта подпись относится к каналу обновления. Она не заменяет Windows Authenticode
или заверение приложения Apple.

## Подготовка следующего выпуска

1. Увеличить Cargo.toml/Cargo.lock, выполнить проверки и получить четыре пакета CI.
2. Сверить artifact digest GitHub, build-info каждой платформы и source_sha256.
3. Сформировать expected-source.json из `scripts/package_launcher.py::source_hashes`.
4. Выполнить `scripts/publish_launcher.py` с четырьмя `--package PLATFORM=DIR`,
   `--version`, `--expected-source`, `--signing-key` и новым `--output`.
5. Сначала разместить неизменяемый launcher-releases/VERSION/, проверить SHA-256,
   затем атомарно заменить launcher-v1.json.

Закрытый ключ находится вне репозитория и каталога сайта, с правами 0600. На рабочем
компьютере текущего выпуска это `~/.local/share/opensc-release-keys/launcher-ed25519.pem`.
Его содержимое не включается в исходники, пакеты, отчёты или CI. Открытый ключ SHA-256:
`27b95b1a80ebd20be39c43bf30935f3e1af81ffcac7779b53dfb72ec434159fc`.
Для нового ключа нужен отдельный план перехода уже установленных клиентов.

Для локальной упаковки сначала сохраните cargo metadata для нужной платформы:

```sh
cargo metadata --locked --format-version 1 --filter-platform x86_64-unknown-linux-gnu > launcher-metadata.json
python scripts/package_launcher.py --cargo-metadata launcher-metadata.json --binary target/x86_64-unknown-linux-gnu/release/opensc-launcher --platform linux-x86_64 --output dist --installers
```

Упаковщик добавляет файлы лицензий, отдельный нативный файл для самообновления и
build-info платформы. На macOS приложение и отдельный файл подписываются ad-hoc
по отдельности; CI запускает --help у обеих форм. Публичный выпуск формируется
из CI, а не из локальной сборки CachyOS.
