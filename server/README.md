# OpenSC web — Rust + Axum

Отдельный HTTP-сервис на Rust/Axum 0.8.9. Раздаёт существующие страницы, установщики
и манифесты, сохраняя GET, HEAD, Range, MIME-типы и потоковую передачу больших файлов.
Лаунчер собирается независимо: его Cargo.lock и выпуск 0.2.0 не изменяются.

Схема: посетитель → Traefik (HTTPS, первый лимит запросов) → opensc-web
(проверка клиента, лимиты, файлы из read-only `/srv/shadow`). База данных пока не нужна.

## Ограничения по одному IPv4-адресу или IPv6-подсети /64

| Запросы | Средняя скорость | Начальный запас |
| --- | --- | --- |
| Все запросы | 120/мин | 40 |
| `/updates/`, кроме файлов выпусков | 60/мин | 20 |
| `/downloads/` и `/updates/releases/` | 12/мин | 8 |

Дополнительный лимит скачиваний — 4 активных передачи на клиента, 32 на сервис.
Слот удерживается до завершения передачи тела или отключения клиента, а не только
до отправки заголовков. HEAD не занимает слот передачи. При ограничении возвращается
429 с `Retry-After`; при общей перегрузке — 503. В памяти хранится не более 10 000 клиентов.
На Traefik дополнительно действуют 180 запросов/мин с запасом 60, до 20 одновременных
запросов на IP и до 128 на домен. В Rust ограничены и рабочие потоки: 2 async + до 16 blocking.

Запросы известных сканеров (sqlmap, nikto, nuclei и другие) и некоторых агрессивных
краулеров получают 403. Пробы `.env`, `.git`, WordPress/PHP-admin и похожих путей
дают 404; после пяти проб за пять минут адрес блокируется на 15 минут.
Query string, кодирование пути и подмена forwarded-заголовков не сбрасывают лимит.
Разрешены только GET и HEAD без тела. Добавлены CSP, nosniff и запрет встраивания.

Это защита от сканирования и чрезмерной активности. User-Agent можно подделать,
а распределённую атаку на пропускную способность сервера эти меры полностью не устраняют.
Капча и внешние платные сервисы не подключены. `robots.txt` — лишь инструкция
добросовестным роботам; реальное ограничение выполняет сервер.

## Адрес клиента и прокси

`OPENSC_TRUSTED_PROXY_HOST=traefik` включает режим доверенного прокси. Сервис
разрешает входящие запросы только от IP, полученных из Docker DNS для этого имени,
и принимает единственный `X-Real-IP`. Список обновляется каждые 30 секунд.
`X-Forwarded-For` не используется в качестве идентификатора. На Traefik не включать
`forwardedHeaders.insecure`: он должен очищать присланные извне forwarded-заголовки.
Внешний порт контейнера не публикуется. Встроенный `/healthz` доступен локальному
healthcheck без forwarded-заголовков.

Без `OPENSC_TRUSTED_PROXY_HOST` используется IP TCP-соединения, а forwarded-заголовки
игнорируются. Такой режим подходит для локального запуска:

```sh
OPENSC_WEB_ROOT="$PWD/deploy/site" OPENSC_WEB_BIND=127.0.0.1:8780 \
  cargo run --manifest-path server/Cargo.toml --locked
```

## Проверки и сборка

```sh
cargo fmt --manifest-path server/Cargo.toml --check
cargo test --manifest-path server/Cargo.toml --locked
cargo clippy --manifest-path server/Cargo.toml --locked --all-targets -- -D warnings
```

Workflow `server.yml` собирает статический `x86_64-unknown-linux-musl`, запускает
тесты и проверяет Docker-образ `FROM scratch`. Контейнер работает от UID 65532,
без shell, root-прав и записываемой корневой ФС. Артефакт включает SHA-256 и исходный коммит.

На сервере сначала собирается новый локальный образ с тегом от хеша бинарного файла
и запускается `opensc_web` в отдельном Compose-проекте `opensc-web`. После healthcheck
атомарно меняется только `/opt/traefik/data/dynamic/shadow-company.yml`. Старый Nginx
сохраняется для отката. Конфигурация других доменов, DNS и получение сертификатов
не меняются. До изменения сохраняются старый HTML и конфигурация маршрута.

Шаблоны: `compose.yml`, `traefik.yml`. Compose-файл производства хранится в
`/opt/shadow-company/web.yml` и содержит конкретный проверенный тег образа.


## Багрепорты (0.2.0)

В compose добавлен OPENSC_REPORT_DB и отдельный постоянный том reports. Перед
запуском создайте /mnt/data/shadow-company/reports и reports/backups с владельцем
65532:65532 и правами 0700. Публичный каталог сохраняет прежний отдельный read-only том.
Через API принимается только POST /api/v1/bug-reports; список и содержимое
обращений доступны через SSH CLI. Описание формата, статусов и восстановления:
[BUG-REPORTS-RU.md](../docs/BUG-REPORTS-RU.md).

После проверки резервной копии установите backup-reports.sh в /opt/shadow-company/,
а opensc-reports-backup.service/timer в /etc/systemd/system. Таймер делает снимок
ежедневно после 03:30 UTC с распределением до 15 минут; Persistent=true позволяет
выполнить пропущенный запуск после включения. Копии не удаляются автоматически.
Откат веб-образа сохраняет каталог базы и резервные копии.
