# Стойки, UZI и группа охраны

После разрезания сетки и пролезания выбери Джона. **S — стоять, C — присесть, P — лечь**. Обычный ЛКМ по земле задаёт ходьбу или ползание в выбранной стойке; двойной ЛКМ включает соответствующее ускоренное движение. Ctrl+P сохраняет назначение паузы. H останавливает движение и действие, сохраняя стойку; уже начатый переход заканчивается. Home возвращает стоящего невооружённого Джона и исходное состояние всех девяти подключённых противников.

Стойка меняется через шесть исходных переходных клипов. Приказ движения, выданный во время перехода, ждёт его завершения. Открытый инвентарь, паузящая подсказка и пауза останавливают игровые часы. Приказы смены стойки не проходят через окна интерфейса и не применяются к невыбранному бойцу. Смена стойки отменяет текущий подбор, резание или атаку.

UZI уже лежит в исходной точке MTF **`[1, -667]`**: `[8070.2275390625, 9532.9833984375, 1216]`. После прохода он находится в следующем участке лагеря; переведённая точка на земле — около `[80.70, 12.10, -95.33]` м. Подбор выполняется ЛКМ. В приседе и лёжа используются свои клипы подбора и callback, поэтому предмет не появляется в руках раньше соответствующего кадра.

**UZI автоматически не экипируется**: оригинальный профиль содержит `OBJECT_AUTO_EQUIP FALSE`. Открой Space, перетащи UZI в основной слот и закрой инвентарь. Нож, BDA и кусачки сохраняются. Магазины BDA и UZI учитываются отдельно; переключение оружия не пополняет их.

ЛКМ по охраннику задаёт атаку основным оружием. Для BDA и UZI подключены исходные прицеливание и стрельба стоя, в приседе и лёжа. Выбор нового противника, смена стойки, H или новый приказ отменяют старую атаку. Дистанция и линия огня проверяются перед каждым выстрелом.

## Исходные параметры

| Источник | Используемые данные |
|---|---|
| `guns.txt`, `Uzi` | `AlItGn-Uzij`, правая рука, `CSTYLE_RIFLE`, магазин 32, дальность 2500 исходных единиц = 25 м |
| Профиль очереди | До трёх выстрелов, `BURST_ROUND_DELAY 80` мс, `FIRE_DELAY 250` мс |
| `shell_damage_models.txt` | 9MM, базовый урон 27; модификатор UZI 95 |
| `audio_defs.txt` | Исходный `AUDIO_W_SMG_UZI_3`; один запуск звука при начале очереди |
| `mot_sequencer_defs.txt` | Статические позы, шесть переходов, ходьба/бег в приседе, медленное/быстрое ползание, движения с винтовочным стилем |
| `DEFAULT_COG_POSITION` | Таз без собственного ключа положения: стоя `[0, 0, 102.474800]`, в приседе `[0, 0, 44.049500]`, лёжа `[0, 0, 23.300262]` |
| `ai_smg.txt` и MTF | Шесть бойцов: `[6,-815]`, `[6,-814]`, `[6,-813]`, `[6,-662]`, `[6,-663]`, `[6,-664]`; исходные профили, позиции и повороты |
| CER | Подбор UZI → help 11 через 1000 мс; гибель всей `AI_SMG` → `obj_eliminate_guards` и help 12 через 1000 мс |

Четвёртая основная задача завершается **после всех шести** охранников. Подбор оружия, первый убитый боец и пролезание не завершают её. После этого выполнены четыре из шести основных задач и становится доступна задача захвата техники. Лечение и техника пока относятся к следующим этапам.

## Применение BMF

В исходных `bipedal_crouch` и `bipedal_prone_into_fire` есть каналы ID 81–83, которых нет в теле Джона. В EXE участок `0x0049D620–0x0049D629` ищет узел по ID и пропускает отсутствующий. `Clip` теперь следует этому правилу. Существующие узлы получают свои ключи, структура BMF, маски, ссылки и конечность чисел по-прежнему проверяются парсером.

Статические позы crouch/prone не содержат положения таза. Для них применяется исходный `DEFAULT_COG_POSITION`; явный ключ положения таза имеет приоритет. Это устраняет зависание низкой позы на высоте стоящего бойца. Перемещение по карте накапливается из корневых BMF-дельт и переводится в метры через масштаб карты 0.01. Горизонтальное перемещение переходных клипов пока не применяется.

## Границы точности

Расписание очереди сейчас трактует 250 мс как паузу после последней пули перед следующей очередью; внутри неё интервал 80 мс. Таймер сохраняет остаток между кадрами и обрабатывает выстрелы, срок которых наступил, поэтому размер кадра не меняет расход патронов. Случайная задержка, разброс и накопление ошибки прицеливания ещё не восстановлены. Урон прототипа — `27 × 95 / 100 = 25.65` за попадание: это выбранная формула из исходных чисел, точная формула EXE не подтверждена. В этой модели на каждого охранника с 75 HP приходится три попадания.

Шесть охранников отображаются и принимают урон в исходных позициях. Патрулирование, обнаружение, ответный огонь и исходные цели группы AI ещё не исполняются. Общего поиска маршрута и столкновений со зданиями нет; столкновения с ограждениями остаются на уровне земли, без проверки высоты тела. Линия огня использует прежнюю точку бойца; точная высота прицеливания для каждой стойки ещё не восстановлена. Анимации удара ножом и броска гранаты остаются стоячими временными действиями; постоянная стойка после них сохраняется.

## Запуск и изучение кода

```bash
# Полная цепочка от ножа до шестого охранника, без окна:
./scripts/dev.sh cargo run --locked -p shadow-model-viewer --bin shadow-map-viewer -- \
  --game-dir "/путь/к/игре" --player on --player-action smg \
  --player-seconds 300 --player-json /tmp/smg.json

# Оконная проверка той же цепочки, S/C/P и переноса UZI в инвентаре:
./scripts/dev.sh cargo run --locked -p shadow-model-viewer --bin shadow-map-viewer -- \
  --game-dir "/путь/к/игре" --window 1280x720 \
  --smg-smoke-json /tmp/smg-window.json --screenshot /tmp/smg-window.png
```

В `stance.rs` enum `Posture` задаёт постоянную стойку, таблицы индексов ссылаются на уже загруженные клипы. В `player.rs` проследи `request_posture → posture_transition → step`: переход временно удерживает движение, но сохраняет его цель. В `smg.rs` подбор меняет владение предметом, а `Inventory::equip` — активный предмет. В `combat.rs` отдельный счётчик очереди расходует по одному патрону, а `complete_smg` проверяет всю группу и выдаёт событие однократно. [Проверки](VALIDATION-RU.md).
