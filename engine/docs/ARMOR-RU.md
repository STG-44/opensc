# Бронежилет Джона

После аптечки подбери Flak Jacket щелчком ЛКМ на карте. Джон подходит к исходной точке предмета и надевает бронежилет на кадре подбора. Открой инвентарь через Space: **ЛКМ по строке «Тело»** снимает бронежилет и возвращает форму; повторный щелчок надевает его. Оружие, патроны и аптечка сохраняются. Home возвращает предмет на карту и начальную форму. В меню паузы состояние одежды сохраняется.

## Данные оригинала

- `maps/training_final.mtf`: Flak Jacket, ID `[1,-769]`, положение `[5561.97119140625,10616.5810546875,1210]`, поворот `[0,0,0]`. Модель предмета — `AlItTl-Kevlarvest`.
- `config/inventory_object_profiles/outfits.txt`: `EQL_BODY`, `CSTYLE_ONE_HAND`, `BODY_TYPE BT_FLAK`, `OBJECT_AUTO_EQUIP FALSE`.
- В профиле Джона `BT_UNIFORM` и `BT_FLAK` используют одинаковые тело `Man1_LP`, голову и рюкзак. Меняется только `BODY_MAP`: `Man1_John.BMP` → `Man1_John_flak.BMP`. В Bevy заменяются текстуры материалов частей тела; модели головы, рюкзака и оружия сохраняются.
- `CET_OBJECT_PICKED_UP:Flak Jacket` вызывает исходную `help_combat_15` через 1000 мс один раз. Подсказка прямо говорит, что предмет попал в слот тела и уже надет. При этом флаг `OBJECT_AUTO_EQUIP` в конфиге — FALSE. Прототип заполняет свободный слот первым предметом одежды; точное правило оригинального EXE ещё не восстановлено. Начальная форма считается внешностью по умолчанию, отдельный предмет формы не создаётся.
- Задача `obj_secure_armor` закомментирована в исходном сценарии. Подбор не увеличивает число завершённых задач: после четырёх боевых задач следующей остаётся `obj_secure_vehicle`.

Одна описательная строка Uniform в оригинальном outfits.txt содержит незакрытую кавычку. Загрузчик одежды пропускает только `OBJECT_DESC_LINE`, которые здесь не используются; игровые поля разбираются строгим общим парсером. Общий парсер не ослаблен.

## Защита и границы этапа

Импортируются `ARMOR_BLAST_MULT 0.9`, LIGHT/HEAVY `DR 10 / DD 1`, MELEE `DR 0 / DD 1`. Проверяются конечные неотрицательные числа и положительные DD. **Влияние этих параметров на входящий урон пока не подключено**: ответная стрельба ИИ и точная формула DR/DD предстоят. Ранение у аптечки использует прежнюю временную модель и не учитывает броню.

Сейчас поддерживается исходный бронежилет Джона и совместимые замены его текстуры. Замены профиля одежды, меняющие геометрию тела, голову или рюкзак, отклоняются до создания сцены. Общий гардероб, другие виды брони, перенос/выбрасывание одежды и полный рюкзак оригинала предстоят.

## Числовой пример

Из папки проекта:

```bash
./scripts/dev.sh cargo run --locked -j1 -p shadow-model-viewer --bin shadow-map-viewer -- \
  --game-dir "/путь/к/Shadow Company" --player on \
  --player-action armor --player-seconds 420 --player-json /tmp/shadow-armor.json
```

Пример проходит предыдущие участки обучения, лечение и подбор брони. Только в этом числовом примере подсказки подтверждаются автоматически. Проверка окна: `--player-action medical --player-seconds 360 --armor-smoke-json /tmp/shadow-armor-window.json --screenshot /tmp/shadow-armor.png`. Она проверяет подбор мышиным приказом, материалы тела, скрытие предмета, снятие и повторное надевание через инвентарь. Обычный запуск обучения не пропускает предыдущие этапы.

Для изучения Rust смотри `armor.rs`: `Armor` хранит состояние предмета, `Protection` — исходные числа, а `BodySurface` отмечает только материалы тела. `Handle<Image>` позволяет переключать уже загруженные текстуры без повторного чтения архива. При выходе из обучения освобождаются обе текстуры, включая ту, которая сейчас не отображается.

После брони доступен [Hummer: посадка, движение и выход](VEHICLE-RU.md). Надетая броня сохраняется за рулём и после выхода.
