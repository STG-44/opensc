# Hummer в обучении

После бронежилета выйди из помещения и щёлкни **ЛКМ по Hummer**. Джон подходит к борту и занимает водительское место. **↑ / ↓** разгоняют машину вперёд / назад, **← / →** поворачивают передние колёса. **H** останавливает машину. При посадке включается слежение камеры; **T** переключает его, Numpad и колесо сохраняют управление камерой.

Для выхода остановись, нажми **E** или кнопку «Выйти из Hummer», затем **ЛКМ по свободной земле внутри круга**. Кузов, препятствие и точка за кругом отклоняются. ПКМ отменяет выбор выхода. Во время выбора точки машина не едет. После выхода сохраняются оружие, патроны, аптечка и бронежилет. Инвентарь и действия пехоты во время управления машиной заблокированы.

Ctrl+P приостанавливает движение, Esc в основном приложении открывает меню. Home возвращает машину, Джона и снаряжение к началу обучения. В машине модель Джона скрывается; после выхода показывается снова. Анимация дверей и посадки пока отсутствует.

## Источники оригинала

- `maps/training_final.mtf`: класс `4x4`, Hummer ID `[1,-767]`, положение `[3984.17333984375,10421.775390625,1210]`, поворот `[0,0,3.1825129985809326]`.
- `models/alvhqd-hummer/alvhqd-hummer.smf`: исходные кузов и четыре колеса; место водителя берётся из узла `seat1`. В модели также есть seat2–seat4, но управление несколькими пассажирами пока не реализовано. База колёс вычисляется по Gcp1/Gcp3. Используется существующий объект карты, второй экземпляр машины не создаётся.
- `config/vehicle_var_defs.txt`: `mass 15000`, `fwd_power 35000`, `rvs_power 15000`. Загрузчик проверяет конечные положительные значения. Параметры читаются через общий каталог с поддержкой замен.
- `config/keyboard_defs.txt`: LEFT/RIGHT/UP/DOWN — управление техникой, E — `KM_FUNC_EXIT`.
- `help_combat_15` описывает ЛКМ по машине и стрелки. `help_combat_16` описывает выбор выхода через значок бойца и круг на земле. Сейчас этому соответствует отдельная кнопка выхода; полный оригинальный портретный интерфейс ещё предстоит.
- `CET_VEHICLE_OCCUPIED:AlVhQd-Hummer` завершает `obj_secure_vehicle`, включает `obj_rescue_beecher` и вызывает `help_combat_16` через 1000 мс. CER удаляется после первого срабатывания. Повторная посадка не повторяет подсказку и не добавляет задачу.

Модель перемещается и вращается в исходном масштабе 0.01. Колёса вращаются по пройденному пути и поворачиваются при рулении. Вместе с кузовом перемещаются треугольники проверки видимости: на прежнем месте машины не остаётся невидимого препятствия.

## Временная физическая модель

Формула физики оригинального EXE ещё не восстановлена. Сейчас применяется кинематическая модель: `power / mass` трактуется как ускорение в м/с², скорость ограничена 12 м/с вперёд и 4 м/с назад, угол руля — 0.55 рад, замедление без газа — 1.6 м/с². Поворот учитывает скорость и базу колёс. H останавливает мгновенно. Радиус выхода 4 м и дистанция подхода 0.6 м — параметры прототипа. Это не подтверждение числового совпадения с оригиналом.

Для движения проверяется весь повёрнутый след кузова против ограничивающих коробок непрозрачных статических meshes. Расчёт делится на шаги не длиннее 1/120 с; выход за рельеф отклоняется. Коробки могут перекрывать больше пространства, чем реальная геометрия. Прорезанная сетка исключается из препятствий. Для [ворот перед Джеком](GATE-RU.md) теперь отдельно учитываются обе боковые секции и подвижная створка, включая альфа-маску. Остальная проверка учитывает непрозрачные части: другие прозрачные сетки и растительность с альфа-маской сами по себе машину не блокируют. Система не моделирует подвеску, наклон кузова на склоне, прыжки, воду, повреждения от столкновений, раздавливание персонажей или разрушение объектов. Звуки двигателя, пассажиры и оружие техники ещё не подключены. Пешеходный обход препятствий остаётся прежним отдельным ограничением.

## Проверка и изучение кода

Из папки проекта:

```bash
./scripts/dev.sh cargo run --locked -j1 -p shadow-model-viewer --bin shadow-map-viewer -- \
  --game-dir "/путь/к/Shadow Company" --player on \
  --player-action vehicle --player-seconds 480 --player-json /tmp/shadow-vehicle.json
```

Этот числовой пример проходит предыдущие участки и занимает Hummer. Подсказки подтверждаются автоматически только в примере. Проверка окна: `--player-action armor --player-seconds 420 --vehicle-smoke-json /tmp/shadow-vehicle-window.json --screenshot /tmp/shadow-vehicle.png`.

В `vehicle.rs` состояние посадки отделено от скорости и режима выхода. `board` исполняет событие сценария, `drive` считает движение, `exit` проверяет точку. `visuals` обновляет исходный объект карты и видимость бойца. В `pickup.rs` метод `move_object` переносит геометрию видимости. Попробуй проследить путь команды ↑ от Bevy Input до изменения исходного MapObject.
