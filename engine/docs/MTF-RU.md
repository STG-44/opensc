# Первая карта: MTF, PCX и SMF

```bash
./scripts/demo-map.sh
# Приближённый вид учебной площадки:
./scripts/demo-map.sh "/путь/к/игре" camp
```

В Windows: `scripts/demo-map.ps1 -GameDir "C:\Games\Shadow Company" -Camera camp`. WASD перемещают камеру, ЛКМ и стрелки вращают её, колесо меняет расстояние. Home показывает всю карту, C возвращает к учебной площадке.

## От ресурсов к сцене

`maps/training_final.mtf` — текст в Windows-1252. `OBJECT` и `OBJECT_INVENTORY` объявляют класс, ссылку на модель и имя. Следующие строки содержат `OBJECT_POSITION`, `OBJECT_ROTATION` и `OBJECT_ID`. Парсер учитывает кавычки и комментарии `;`, проверяет числа и обязательные свойства. Глобальные и дополнительные команды сохраняются как токены; игровая логика не исполняется.

В Ecuador найдено исходное `-1.#IND00` вместо одной высоты. Такое Microsoft-обозначение неопределённого числа сохраняется в свойствах, а `position` становится `None`. Просмотрщик пропускает этот объект с объяснением. Это позволяет исследовать остальные записи без подмены повреждённого положения нулём. Обычные неверные числа и NaN по-прежнему отклоняются.

Рельеф хранится в `maps/training.pcx`: одноплоскостной PCX v5, RLE, 8-битные индексы. `pcx.rs` проверяет заголовок, размеры, stride, серии RLE, padding строк и необъяснённый остаток. Палитра не используется для вычисления высоты. Это читатель карт высот, не универсальный декодер всех вариантов PCX.

`textures/terrain/training/terrain_mapping.txt` задаёт 64×64 отсчёта и расстояние между ними 200 исходных единиц. При постоянных `min_alt_grad = max_alt_grad = 1` высота равна `(255 - индекс PCX) × altitude_map_height_base`. Для training шаг высоты — 10; индекс 134 даёт 1210. Случайная таблица высот пока возвращает явную ошибку.

Ячейка разбивается по диагонали `(0,0) → (1,1)`. `TerrainGrid::height_at` использует те же два треугольника, что и Bevy mesh, поэтому результат отличается от билинейной интерполяции. Поверхность берётся из `trnhigh/training.jpg`, атлас 1024×1024. UV рассчитаны относительно `width × edge`, а не растянуты до последнего отсчёта. Нарисовано 63×63 ячейки между 64×64 известными отсчётами; замыкание крайней полосы оригинального рендера пока не воспроизведено.

Статические SMF загружаются без индивидуального нормирования размеров. `header_vector` сохраняется как метаданные и не растягивает геометрию. Начальная поза узлов учитывает исходный выбор Euler/кватерниона, описанный в [SMF-RU.md](SMF-RU.md). Общий корень карты переводит исходные единицы в метры коэффициентом 0.01, а оси — из `(x,y,z)` в `(x,z,-y)`. Текстовые углы применяются как Euler ZYX через тот же перевод осей; точное соответствие всех наклонов оригинальному EXE ещё предстоит проверить.

Модель и текстура загружаются один раз и повторно используются через `Handle`. Ссылки `_LOD` разрешаются через первый `SUB_MODEL_MODEL` исходного профиля: используется детальная модель, переключения по расстоянию пока нет. Неоднозначный basename отмечается только у объекта, который его использует.

## Проверка без окна

```bash
cargo run --locked -p shadow-tools -- maps --game-dir "/путь/к/игре" --json
cargo run --locked -p shadow-tools -- heightmap --game-dir "/путь/к/игре" \
  --asset maps/training.pcx --json
cargo run --locked -p shadow-model-viewer --bin shadow-map-viewer -- \
  --game-dir "/путь/к/игре" --scene-json training-scene.json
```

Последняя команда подготавливает настоящую геометрию без GPU и записывает список экземпляров, моделей, текстурных проблем и параметры рельефа. Каталог `--overrides` работает для MTF, PCX, конфигураций, SMF и текстур.

## Границы этапа

Это статический просмотр учебной карты: 267 видимых статических экземпляров из 51 модели. Две записи с исходными SMF без треугольников пропущены и перечислены в отчёте. Бойцы из MTF пропускаются; анимированный Питер с АК-47 пока живёт в отдельном `shadow-character-viewer`. Нет условий миссии, ИИ, выбора отряда, навигации, столкновений, воды, неба, исходных эффектов освещения и переключения LOD. Другие карты можно исследовать командами форматов; визуально проверяется training. Полное совпадение кадров со старым EXE не заявляется.

## Изучение Rust

1. `text.rs`: конечное состояние `quoted` позволяет отличить комментарий от точки с запятой в имени.
2. `mtf.rs`: `Option<[f32; 3]>` выражает отсутствие пригодного положения, а `Result` — ошибку структуры файла.
3. `pcx.rs`: цикл RLE ограничивает каждую серию размером строки и удаляет padding.
4. `terrain.rs`: конфигурация и индексы превращаются в высоты и выбор одного из двух треугольников.
5. `map_scene.rs`: `BTreeMap` повторно использует модели; `scene.rs` сохраняет исходный масштаб вместо размеров витрины.
6. `map.rs`: общая сущность-корень масштабирует карту, дочерние сущности хранят расстановку объектов, `Handle` позволяют разделять meshes между экземплярами.

Упражнение: добавь переключатель сетки рельефа или отображение имени объекта по выбору мышью. Следующий игровой этап — присоединить анимированного бойца к этой карте и поставить его на высоту `height_at`.
