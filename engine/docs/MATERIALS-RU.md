# Прозрачность оригинальных текстур

Проверено 12 октября 2026 года по BMP/RAW из `textures.gut` и коду загрузчика восстановленного `shadow.exe`. Исходные файлы игры не меняются.

## Причина чёрных прямоугольников

BMP сетки и колючей проволоки содержит RGB, без альфа-канала. Чёрный фон — область, которую оригинал делает прозрачной. Ранее Bevy получал `AlphaMode::Opaque`, поэтому рисовал фон как поверхность.

В `asset_mesh.rs` изображение переводится в RGBA8 с сохранением sRGB и настроек повторения/фильтрации. Файл BMP/JPG с `_ck` в имени использует чёрный ключ: RGB `(0, 0, 0)` получает альфу 0. Остальные пиксели сохраняются. Материал получает `AlphaMode::Mask(0.5)`, чтобы сетка имела отверстия и корректную глубину. Чёрные пиксели обычных текстур остаются непрозрачными.

Для BMP/JPG загрузчик ищет RAW с тем же путём и именем без расширения. RAW содержит один байт альфы на пиксель, строки сверху вниз. Он имеет приоритет над ключом. Мягкие края используют `AlphaMode::Blend`. Собственный неполностью непрозрачный альфа-канал изображения сохраняется; PNG использует собственную альфу без устаревшего RAW.

Каталог и здесь сохраняет порядок `GUT < Data < overrides`. Если улучшенный BMP меняет размер, нужно заменить вместе с ним RAW. Несовпадение размеров возвращает понятную ошибку; статическая модель показывает розовый материал и записывает причину, вместо некорректного чтения маски.

| Оригинальная текстура | Обработка |
|---|---|
| `fencediff_ck.bmp` | Чёрный ключ для сетки |
| `constantinacomp_ck.bmp` | Чёрный ключ для колючей проволоки |
| `southtreebranch1.bmp` + `.raw` | Отдельная маска листвы |
| `rock1.bmp`, `rock2.bmp` | Обычная непрозрачная поверхность |

## Подтверждение формата

`0x48A460` ищет строку `_ck` в имени. `0x48ACD0` заменяет расширение на `raw` и для 24-битного BMP/JPG загружает дополнительный канал. `0x48747D`/`0x4874A9` сопоставляет RAW по индексу `y * width + x` с верхней строкой поверхности, хотя строки BMP считываются снизу. `0x48B210` включает цветовой ключ 0 для обычной 24-битной текстуры `_ck`. Ключ индексированного 8-битного оригинала и все старые режимы материалов ещё не воспроизведены точно; современное освещение и фильтрация могут отличаться.

## Откуда берётся геометрия

Карта читает положение и углы объектов из MTF. Вершины и грани берутся из SMF с учётом иерархии узлов. Для Bevy исходные оси преобразуются `(x, y, z) → (x, z, -y)`, затем вся карта масштабируется в 0.01. Рельеф создаётся из исходной PCX-карты высот и её параметров `terrain_mapping.txt`, а не из яркости цветной текстуры. Карта и высота бойца используют одни и те же треугольники.

На `training_final.mtf` нет ссылок на отдельные модели скал `anscms-rock*`. В оригинальном архиве эти модели есть и имеют объёмную геометрию. Нарисованный каменистый участок на общей текстуре поверхности сам по себе не является отдельным 3D-объектом. Без указания конкретного места нельзя считать любой плоский камень ошибкой загрузки.

## Изучение Rust

Проследи `image()` → `apply_alpha()` → `Texture` → `PreparedPart.alpha_mode` → `StandardMaterial`. `Option<&[u8]>` означает наличие или отсутствие RAW; `Result` передаёт ошибки размеров. Тест с синтетическим BMP и RAW проверяет порядок строк и замены через каталог. Обработка общая для одиночной модели, карты и частей персонажа.
