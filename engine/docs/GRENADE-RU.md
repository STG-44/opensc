# Frag Grenade и третий часовой

Запусти `./scripts/demo-game.sh`, выбери обучение и пройди нож и BDA. После гибели второго часового рядом с телом появляется Frag Grenade с золотым кольцом. Выбери Джона и щёлкни по гранате ЛКМ. Подбор по callback кладёт одну гранату в дополнительный слот; BDA остаётся основным оружием и сохраняет патроны. Space открывает инвентарь, где виден дополнительный слот.

После закрытия подсказки выбери Джона и нажми **ПКМ по третьему часовому**. Боец подойдёт на дальность и бросит гранату. **Shift+ПКМ по земле** задаёт принудительную точку броска. Обычный бросок проверяет линию до цели; принудительный допускает приказ за преграду, но полёт всё равно сталкивается со сплошными SMF и рельефом.

Граната появляется в кисти на время подготовки и отделяется в кадре callback. Именно тогда расходуется предмет и запускается запал. H или другой приказ отменяют подготовку; уже выпущенная граната продолжает лететь. Пауза, инвентарь и паузящая подсказка останавливают время прототипа, в том числе запал. Home сбрасывает бойцов, предметы, полёт и сценарий.

## Исходные данные

| Источник | Использование |
|---|---|
| `grenades.txt`, Frag Grenade | `AlItEx-GrenadeFrag`, правая рука, `OBJECT_AUTO_EQUIP FALSE`, запал 3500 мс, дальность 2500 единиц = 25 м |
| `help_combat_6` | Автоматическое назначение в свободный дополнительный слот и ПКМ/Shift+ПКМ |
| `MSEQ_STAND_THROW_GRENADE` | Оригинальный BMF; `MCB_FIRE_WEAPON` в кадре 7, время вычисляется по FPS файла |
| `shell_damage_models.txt`, GRENADE_FRAG | `BLAST_RADIUS 1100` = 11 м, `BLAST_FORCE 15000`, BASE/RAND_DAMAGE сохранены в диагностике |
| `AUDIO_EXP_GRN_FRAG` | Оригинальный `exp_grn_frag.wav`, загруженный через каталог с поддержкой overrides |
| `AI_Grenade → Soldier_Training_Unarmed_002 → MTF [5, -876]` | Третий часовой, 75 HP, Man1_enemy/Head_AngolaRebel; позиция и поворот из MTF, высота из PCX |

Гибель третьего часового посылает события HumanKilled и AllPlayersInfantryKilled для `AI_Grenade`. CER завершает `obj_eliminate_sentry3`, включает `obj_eliminate_guards` и через 1000 мс показывает `help_combat_8`. Сценарий пропускает седьмую подсказку. Следом уже подключены [кусачки, разрезание и проход через сетку](FENCE-RU.md).

## Границы точности

Модель, анимация, callback, запал, дальность, радиус, звук и цепочка заданий читаются из оригинальных данных. **Полная формула взрыва и баллистика оригинального EXE ещё не восстановлены.** Временный урон в центре — `BLAST_FORCE × 0.01 = 150`, с линейным спадом до 0 на 11 м и блокированием сплошными SMF. Осколки, броня, случайный урон и повреждение Джона ещё отсутствуют. Третий часовой стоит на месте и не отвечает на атаку.

Прототип использует параболу с расчётным временем до цели 1.2 с, гравитацию 9.81 и уменьшение скорости отскока до 35%; это наши временные правила. Расчёт разбит на шаги до 1/60 с и проверяет отрезок перемещения, чтобы уменьшить прохождение сквозь стены. Прозрачные маски и точные свойства поверхностей в физике ещё не участвуют. Визуальный взрыв — короткая светящаяся сфера, не воспроизведение оригинального эффекта. Положение предмета возле тела также приблизительное.

Дополнительный слот пока рассчитан на Frag Grenade и автоматически назначается при подборе. Перенос гранат между слотами, стопки и другие дополнительные предметы ещё предстоят. BDA и нож переключаются как прежде.

## Проверить и изучить

```bash
# Числовая цепочка до третьей задачи, без графического окна:
./scripts/dev.sh cargo run --locked -p shadow-model-viewer --bin shadow-map-viewer -- \
  --game-dir "/путь/к/игре" --player on --player-action grenade \
  --player-seconds 180 --player-json /tmp/grenade.json

# Автоматический проход в окне:
./scripts/dev.sh cargo run --locked -p shadow-model-viewer --bin shadow-map-viewer -- \
  --game-dir "/путь/к/игре" --window 1280x720 \
  --grenade-smoke-json /tmp/grenade-window.json --screenshot /tmp/grenade-window.png
```

В `grenade.rs` проследи `order_throw → callback → Flight → fuse → blast_damage → Tutorial::fire`. `Option<ThrowOrder>` хранит намерение, а `Option<Flight>` — выпущенный предмет: отмена приказа не удаляет существующий полёт. Затем сравни обычные структуры Rust с системами `setup`/`sync`, которые обновляют сущности Bevy. Результаты проверок находятся в [VALIDATION-RU.md](VALIDATION-RU.md).
