# Загрузка настоящих моделей SMF

Добавлен независимый читатель **Sinister Model File 1.0 и 1.1** в `shadow-formats/src/smf.rs` и приложение `shadow-model-viewer`. Оно получает модель и BMP/JPEG/PNG через тот же `AssetCatalog`, поэтому отдельные файлы Data и наши замены имеют прежний приоритет.

## Проверенные данные

Структура сначала разобрана отдельной Python-читалкой, затем сверена с последовательностью чтения оригинального загрузчика в `shadow.exe`. Rust-реализация сопоставлена со всеми **995 SMF** из восстановленного `models.gut`. EXE используется как исследовательский источник; приложение его не запускает и не подключает.

| Данные | Количество |
|---|---:|
| SMF 1.0 | 382 |
| SMF 1.1 | 613 |
| Узлы иерархии | 8 670 |
| Части модели / meshes | 2 848 |
| Вершины | 148 864 |
| Треугольники | 158 456 |
| Вершины с некорректной исходной нормалью | 5 315 |

Совпали версия, имена, числа и флаги заголовка, родители узлов, перемещения/кватернионы, записи границ, имена частей и текстур, числа вершин/граней. SHA-256 канонического представления геометрии совпал для всех 2 848 meshes: каждая вершина, её ID, позиция, два целочисленных поля цвета, UV, пригодная нормаль или признак её отсутствия и каждая грань. Это подтверждает разбор данных. Воспроизведение оригинальных материалов, анимаций и поведения объектов ещё требует реализации и сравнений с оригиналом.

В исследованном каталоге **212 ссылок от частей модели на непустую текстуру не разрешились**. Среди них есть PSD и старые имена ресурсов. Это число ссылок, а не количество уникальных отсутствующих файлов. Возможные сопоставления из конфигурации игры ещё не реализованы.

## Структура файла

Все числовые поля little-endian. Перед бинарными данными находится текстовая преамбула и сигнатура `1a fa 31 c1 de ed 42 14`. Смещения зависят от длины преамбулы.

1. Версия: 16 байт; имя модели: 128 байт. Строки заканчиваются NUL, декодировка Windows-1252.
2. Один f32 заголовка, три f32 служебного вектора, u32 флагов и u32 количества узлов. Первое поле хранится как `radius`; его физический смысл ещё требует проверки.
3. Узел: имя и имя родителя по 128 байт, u32 ID, три f32 перемещения, четыре f32 кватерниона, u32 количества meshes, u32 количества записей границ. В версии 1.1 добавлен u32 флагов узла.
4. Mesh: имя и имя текстуры по 128 байт, u32 числа вершин и граней, затем оба массива.
5. Вершина: **44 байта** — u32 ID, xyz f32, два u32 цвета, uv f32, нормаль xyz f32.
6. Грань: **16 байт** — u32 ID и три u32 индекса массива вершин.
7. После всех meshes узла идут его записи границ: **28 байт** — шесть f32 координат и u32 тега. Использование этих записей в столкновениях ещё не реализовано.

Неизвестные биты и теги сохраняются. Имена узлов уникальны; родитель может быть записан позже ребёнка. Читатель строит порядок обхода без рекурсии, проверяет отсутствующих родителей и циклы. Родитель `<root>` обозначает корневой узел.

Проверяются границы файла, числа записей, индексы граней, безопасные ссылки, конечность координат/UV/перемещений и ненулевые кватернионы. Необъяснённый хвост возвращает ошибку. Пределы прототипа: файл 512 МиБ, 16 384 узла, до 4 096 meshes или записей границ на узел, до миллиона вершин/граней в mesh.

## Сцена Bevy

`shadow-model-viewer/src/scene.rs` объединяет перемещения/вращения узлов. Три поля заголовка сохраняются как `header_vector` и не применяются как масштаб: у 59 моделей, в основном техники, они отличаются от `[1,1,1]`, иногда имеют нулевую компоненту. Их точное назначение ещё исследуется. Прежняя интерпретация как scale была исправлена при загрузке карты. SMF использует Z вверх; для Bevy координаты переводятся как `(x, z, -y)`. Эту интерпретацию преобразований ещё нужно сравнить на сложных моделях с кадрами оригинальной игры.

Модель центрируется над сеткой и масштабируется: наибольшая сторона равна трём единицам. **Это масштаб витрины, а не реальные размеры будущей карты.** Исходные вершины и файлы остаются прежними.

Большинство исходных граней имеют clockwise winding; просмотрщик меняет порядок индексов и учитывает отражающий масштаб. Материалы показываются с двух сторон. Нормали преобразуются обратной транспонированной матрицей; NaN, Infinity и нулевые нормали заменяются рассчитанными по треугольникам. Вырожденная геометрия получает конечное резервное направление.

**V текстуры повторно не переворачивается.** Это проверено по UV ящика и исходному атласу `oildrumcomp.bmp`: ящик использует верхнюю область атласа. Текстуры повторяются при UV вне диапазона 0…1. Для BMP/JPG подключены чёрный ключ `_ck` и одноимённые RAW-маски; PNG использует собственный альфа-канал. Подробности — [MATERIALS-RU.md](MATERIALS-RU.md). Цвета вершин и остальные старые режимы смешивания пока не воспроизводятся; освещение — матовые материалы Bevy.

Поиск текстуры: полный внутренний путь, рядом с моделью, `textures/shared/`, затем единственное совпадение имени в `textures/`. Неоднозначное совпадение возвращает ошибку. Отсутствующая или недекодируемая текстура обозначается розовым материалом и сообщением. Шрифт общий с 2D-просмотрщиком; лицензия включена в проект.

## Запуск и снимок кадра

```bash
./scripts/demo-model.sh

./scripts/dev.sh cargo run --locked -p shadow-model-viewer -- \
  --game-dir "/путь/к/оригиналу" \
  --model models/alscct-crate_large/alscct-crate_large.smf \
  --screenshot crate.png
```

Последняя команда сохраняет PNG после 120 кадров и закрывает приложение. На Windows есть те же аргументы у нативного приложения и `scripts/demo-model.ps1`. Результаты проверок находятся в `VALIDATION-RU.md`.

## Изучение Rust

1. В `smf.rs` прочитать `SmfVertex`, `SmfMesh`, `SmfNode`, `SmfModel`: обычные структуры данных без Bevy.
2. Проследить `Reader::take`, `u32`, `finite` и `?`: как ошибка останавливает разбор до выхода за границы массива.
3. Прочитать тест `reads_both_versions_geometry_and_out_of_order_hierarchy`, изменить синтетический треугольник, проверить результат.
4. В `scene.rs` проследить путь от SMF через `Vec` до `Mesh::ATTRIBUTE_POSITION`, `NORMAL`, `UV_0`, `Indices`.
5. В `main.rs` изучить `Orbit`, системы камеры/загрузки, `Mesh3d`, материал, свет и очистку старых ресурсов при смене модели.

Первая BMF-анимация собранного персонажа уже подключена отдельным просмотрщиком: [BMF-RU.md](BMF-RU.md). Положение таза, ходьба и бег уже подключены. Следующие этапы — MTF и сцена карты, затем навигация и игровое движение. Совместимость оригинальных сохранений, миссий и игровая симуляция здесь ещё не реализованы.

## Начальные повороты узлов

`smf_transform.rs` воспроизводит выбор начальной ориентации из функций оригинала `0x00474BB0` и `0x00491050`. Конструктор узла начинает с флага Euler `4` и нулевых углов. Для узла без meshes, но с bounds этот бит снимается; затем добавляются флаги файла. В SMF 1.0 поле отсутствует и добавляется ноль. При активном бите `4` сохранённый кватернион не задаёт поворот покоя. Без этого бита используется сопряжённый кватернион, с переводом соглашения матриц в Bevy. Начальный поворот корня задаётся ориентацией объекта; в одиночном просмотре она нулевая.

Ранее кватернионы каждого SMF-узла применялись без учёта этого выбора. Например, два одинаковых поворота в узлах проволочного забора складывались и опускали геометрию под землю. Новый выбор позы используется и на карте, и в одиночной витрине, и при сборке персонажа. BMF затем заменяет поворот анимируемых узлов, как прежде. Камерные флаги и полное совпадение всех сложных моделей с EXE ещё требуют проверки.
