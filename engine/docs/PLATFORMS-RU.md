# Windows, Linux и macOS

Решение проекта: общий движок и инструменты на Rust + Bevy, нативные сборки для трёх ОС. Текущая среда разработки — CachyOS. Путь к оригиналу выбирается пользователем; наличие Windows EXE и Wine для чтения данных не требуется.

## Матрица сборок

| Платформа | Rust target | Среда проверки в GitHub Actions | Текущий статус |
|---|---|---|---|
| Linux x86-64 | `x86_64-unknown-linux-gnu` | Ubuntu 22.04 | CI прошёл; установка и окно проверены на CachyOS |
| Linux ARM64 | `aarch64-unknown-linux-gnu` | Ubuntu 22.04 ARM | CI: сборка, тесты и Clippy прошли; окно ещё не проверено |
| Windows x86-64 | `x86_64-pc-windows-msvc` | Windows Server 2022 | CI: сборка, тесты и Clippy прошли; окно ещё не проверено |
| macOS Intel | `x86_64-apple-darwin` | macOS 15 Intel | CI: сборка, тесты и Clippy прошли; окно ещё не проверено |
| macOS Apple Silicon | `aarch64-apple-darwin` | macOS 14 ARM | CI: сборка, тесты и Clippy прошли; окно ещё не проверено |

Файл `../../.github/workflows/engine.yml` собирает приложения, запускает тесты форматов и Clippy на каждом target. Версии ОС сборочных машин закреплены; доступные метки сверены с [документацией GitHub](https://docs.github.com/en/actions/reference/runners/github-hosted-runners). Workflow начнёт выполняться после загрузки проекта в репозиторий GitHub с включёнными Actions. Исходники включены в `engine/` репозитория STG-44/opensc. Результаты новых сборок нужно проверять по соответствующему запуску Actions; подготовленная матрица не означает успешную сборку.

CI без графической сессии не подтверждает работу окна, драйверов и ввода. Перед выпуском нужны отдельные проверки запуска на настоящих Windows, macOS и Linux, включая X11 и Wayland. Версии ОС в таблице — среда компиляции, а не обещанный минимальный номер пользовательской ОС. Windows 10/11 и конкретные минимальные версии macOS подтвердим такими проверками. 32-битные системы и Windows ARM пока не входят в матрицу.

## Linux: широкая совместимость

Целевые семейства: Arch/CachyOS, Debian/Ubuntu, Fedora, openSUSE и другие современные дистрибутивы с поддерживаемым Flatpak и графическим драйвером. Для обычных GNU-бинарников используем Ubuntu 22.04 как начальную базу вместо текущего rolling-дистрибутива. Один бинарник всё равно зависит от ABI системных библиотек; это не делает его совместимым с любой исторической версией Linux.

Основной план распространения — **Flatpak** с фиксированным runtime: его базовые библиотеки не привязаны к версии дистрибутива, как описано в [документации Flatpak](https://docs.flatpak.org/en/latest/basic-concepts.html). Сейчас пакет Flatpak ещё не создан. Сначала подтвердим нативные сборки; затем добавим manifest, выбор каталога оригинала с доступом через sandbox и проверки пакета. Дополнительный архив бинарников можно выпускать для опытных пользователей.

X11 и Wayland уже включены набором возможностей Bevy. Поддержка зависит также от архитектуры процессора, доступности runtime и графического драйвера. Дистрибутив с musl не следует считать совместимым с обычным GNU-бинарником; для таких систем нужно проверять Flatpak или отдельную сборку. Аппаратные требования 3D определим после появления сцены с настоящими моделями. Сейчас на Intel HD 4400 окно проверено через программный Vulkan llvmpipe.

Для сборки из исходников на CachyOS нужны Rust и системные зависимости. Устанавливать их следует через `pacman`; проект не меняет систему автоматически. Списки для Arch, Debian/Ubuntu и Fedora находятся в [документации Bevy для Linux](https://bevy.org/learn/quick-start/getting-started/setup/#linux). Зависимости для компиляции не являются списком требований готового Flatpak-пакета.

## Запуск из исходников

Установить закреплённый Rust через rustup. Для Windows нужны MSVC C++ Build Tools и Windows SDK, для macOS — Xcode Command Line Tools; подробности в [официальной настройке Bevy](https://bevy.org/learn/quick-start/getting-started/setup/).

Linux и macOS, из папки проекта:

```bash
./scripts/demo.sh "/путь/к/Shadow Company"
./scripts/demo-character.sh "/путь/к/Shadow Company"
```

Windows, PowerShell, из папки проекта:

```powershell
.\scripts\demo.ps1 -GameDir "C:\Games\Shadow Company" -Overrides "C:\Games\Наши ресурсы"
.\scripts\demo-character.ps1 -GameDir "C:\Games\Shadow Company"
```

Папка замен необязательна. Если политика PowerShell запрещает локальные скрипты, приложение можно запустить напрямую:

```powershell
cargo run --locked -p shadow-viewer -- --game-dir "C:\Games\Shadow Company"
```

В обоих случаях также можно использовать переменную `SHADOW_GAME_DIR` или локальный UTF-8 файл `local/game-dir.txt`. Настройка конкретного компьютера не входит в исходники. Пути с пробелами и кириллицей передаются отдельными аргументами. Bash-скрипты не требуют GNU-вариантов `dirname` и `cat`, а `.gitattributes` сохраняет LF для скриптов при клонировании на Windows.

## Движок и будущий лаунчер

Форматы данных и игровая логика остаются общими. Платформенные операции — расположение пользовательских каталогов, установка обновления, запуск процесса — выделим в небольшой отдельный слой. Ресурсы оригинала остаются в выбранной пользователем папке; наши пакеты и настройки хранятся в доступном для записи пользовательском каталоге.

Один сервер и один адрес `/updates/` могут обслуживать все платформы. В манифесте обновления будут отдельные записи по полному Rust target, с версией, URL, размером, хешем и подписью. ARM64-бинарник не должен попадать пользователю x86-64. В эту итерацию лаунчер и протокол подписей не реализованы.

На Windows замена работающего EXE потребует завершения приложения и отдельного этапа обновления. На macOS подготовим `.app` для каждой архитектуры и подпись/notarization для публичного распространения. В Linux Flatpak сам обновляет установленный движок и runtime; наш лаунчер проверяет версии и обновляет игровые пакеты в пользовательском каталоге. Для варианта с обычным архивом обновление движка сможет выполнять наш отдельный updater. Нельзя рассчитывать, что приложение внутри Flatpak сможет заменить свой установленный бинарник.

## Критерии перед первым публичным выпуском

- Все пять нативных заданий CI завершились успешно.
- Окно, текстуры, кириллица, ввод и изменение размера проверены на целевых ОС; Linux проверен в X11 и Wayland.
- Чтение оригинала и приоритет замен проверены при путях с пробелами, кириллицей и разным регистром.
- Пакеты запускаются на чистых системах без установленного Rust; минимальные версии ОС и требования GPU зафиксированы по результатам.
- Установка и обновление прерываются и возобновляются без повреждения рабочей версии; выбор архитектуры и подписи пакетов проверены.

Эти пункты определяют готовность будущего выпуска. Добавленный workflow сам по себе не означает, что поддержка всех платформ уже подтверждена.

Проигрыватель AVI реализован на Rust для MJPG и PCM16LE; внешние FFmpeg/Windows-кодеки не нужны. Для сборки аудио на Linux требуется ALSA development package (`libasound2-dev`/`alsa-lib`); он уже входит в зависимости Linux CI. Проверка звукового устройства и окна на Windows/macOS пока не выполнена.
