# Ворота перед Джеком

Выбери Джона и щёлкни **ЛКМ по створке ворот**. Он подходит к ближайшей исходной точке Act01/Act02, встаёт и открывает створку. Через открытый проход можно пройти обычным приказом движения. Повторный ЛКМ по створке закрывает её после подхода. H отменяет подход; Ctrl+P приостанавливает подход и анимацию, Esc в основном приложении открывает меню. Home возвращает исходную закрытую створку и начало обучения.

Это проход к следующему участку обучения. **[Джек, исходная реплика и шестая задача теперь подключены](PARTY-RU.md).** Открытие ворот само по себе не завершает `obj_rescue_beecher`. В оригинальном сценарии отдельная задача `obj_open_gate` закомментирована; обработчик `CET_OBJECT_ACTIVATED:AlStFn-ConsertinaFenceGate` лишь удаляет свою подписку.

## Исходные данные

- MTF: `Structure_Swing_Door`, имя `AlStFn-ConsertinaFenceGate`, ID `[1,-756]`, положение `[2381.3359375,3332.56005859375,1211]`, поворот `[0,0,0]`. Преобразование карты прежнее: `(x,z,-y) × 0.01`.
- Модель: `models/alstfn-consertinafencegate/alstfn-consertinafencegate.smf`. Створка — узел **291 / DodDum**, meshes Rail05 и Fence02. Неподвижные Fence и Rail01 остаются на месте. Ось вращения берётся из иерархии модели, точки подхода — из узлов **251 / Act01** и **261 / Act02**. Улучшенные ресурсы загружаются через обычный каталог замен.
- EXE: конструктор `0x4157c0` устанавливает длительность **200 мс**; `0x414b40` вычисляет угол `elapsed / duration × -90°` и ограничивает конечное положение. `0x41f9b0` возвращает линейное отношение времени. `0x415a00` находит узел `0x123 = 291` и переводит градусы в радианы. Створка открывается до **−90°**.
- `help_combat_16`: ЛКМ по воротам выбранным Джоном, затем подойти к Jack. Это описание управления в оригинале, а не отметка готовности второго бойца.

Замена модели должна сохранять узлы 291, 251 и 261, две неподвижные нижние границы и однозначные имена частей створки. Неподдержанная иерархия или отсутствие обязательного узла отклоняются при загрузке.

В коде `gate.rs` состояние подхода отделено от анимации. `training::issue_orders` проверяет луч по треугольникам створки, `update_player` ограничивает пешеходное движение, `gate::tick` меняет состояние и геометрию проверок, `gate::visuals` поворачивает существующие части MapObject. Второй экземпляр ворот не создаётся.

## Столкновения и границы реализации

Закрытая створка и обе боковые секции блокируют пехоту. При открытии проход остаётся закрыт до завершения анимации; затем столкновения проверяются в новой системе координат створки. Боковые секции сохраняют исходные SMF bounds. Проверяется весь отрезок шага с запасом 20 исходных единиц для бойца, поэтому большой шаг не пропускает закрытую дверь. Перенос Home не считается пешеходным движением.

Для Hummer добавлены отдельные коробки обеих секций и повёрнутой створки, в том числе для текстур с альфа-маской. Узкий пешеходный проход не предназначен для машины. Остальные прозрачные ограждения всё ещё имеют ограничения физики, описанные в [VEHICLE-RU.md](VEHICLE-RU.md).

Порядок «подойти и переключить» пока реализован в нашем контроллере. Анимации бойца для входа/выхода из зданий и звуки двери не подключены; автоматическое прохождение и закрытие за бойцом не заявляются восстановленными. Нет обхода препятствий, моделирования удара створкой или раздавливания. Завершение анимации генерирует исходное событие активации; подсказка 18 появляется после [спасения Джека](PARTY-RU.md).

## Проверка окна

Из папки проекта:

```bash
./scripts/dev.sh cargo run --locked -j1 -p shadow-model-viewer --bin shadow-map-viewer -- \
  --game-dir "/путь/к/Shadow Company" --player on --window 1280x720 \
  --player-action armor --player-seconds 420 \
  --gate-smoke-json /tmp/shadow-gate.json --screenshot /tmp/shadow-gate.png
```

Оконный сценарий переносит Джона со снаряжением к исходным воротам. Это тестовая расстановка, а не прохождение дороги на машине. Проверка использует viewport ray и Bevy ButtonInput; физическая мышь проверяется вручную. Во время сценария выполняются ЛКМ по створке, пауза, проход, обратное закрытие и Home.
