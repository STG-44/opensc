# Персонаж, ходьба и BMF

`shadow-character-viewer` собирает Питера Болланда из двух оригинальных SMF и по умолчанию воспроизводит ходьбу `motions/bipedal_stand_walk_rifle.bmf`. Тело — `Man3_SP`, голова — `Head_Peter`, текстуры — `Man3_Peter.BMP` и `Head_Peter.BMP`. Такое сочетание взято из `config/character_profiles/peter_bolland.txt`. В первом примере оно задано в коде; общий загрузчик профилей ещё предстоит написать.

Запуск на Linux/macOS из папки проекта:

```bash
./scripts/demo-character.sh
# После переноса проекта:
./scripts/demo-character.sh "/путь/к/Shadow Company"
```

На Windows:

```powershell
.\scripts\demo-character.ps1 -GameDir "C:\Games\Shadow Company"
```

**W / S / R / G** выбирают ходьбу / стояние / бег / жест рукой. Переход позы занимает 0.25 секунды, позиция на площадке сохраняется. **M** включает движение по площадке или анимацию на месте. **Home** сбрасывает время и позицию. **Space** ставит на паузу, **[ / ]** сдвигают время на один кадр и включают паузу. **1 / 2 / 3** выбирают скорость 0.5× / 1× / 2×. **ЛКМ + движение мыши / стрелки** вращают камеру, **колесо** приближает, **Esc** закрывает окно.

Камера следует за персонажем. Сетка площадки помогает увидеть перемещение; её линии остаются привязаны к целым координатам мира. Площадка под камерой переставляется для непрерывного просмотра. Это демонстрация движения, игровой карты здесь ещё нет.

Без перемещения:

```bash
./scripts/demo-character.sh "/путь/к/игре" "motions/bipedal_stand_walk_rifle.bmf" off
```

На Windows: `.\scripts\demo-character.ps1 -GameDir "C:\Games\Shadow Company" -RootMotion off`.

Можно передать `--overrides`, как остальным просмотрщикам. Например, новая текстура должна сохранять внутренний путь `textures/shared/man3_peter.bmp`. Замены читаются при запуске; горячая перезагрузка персонажа ещё не подключена.

## Формат на диске

Размеры и расположение полей сверены с загрузчиками оригинального EXE: читатель движения `0x0049C130`, кадра `0x0049DFC0`, ключа `0x0049DE70`. Это адреса исследованной Windows-сборки, а не внешние зависимости нового движка. Парсер Rust не запускает EXE.

Все числа little-endian. Заголовок — **176 байт**:

| Смещение | Поле |
|---|---|
| `0x00` | Имя, 128 байт, Windows-1252, NUL |
| `0x80`, `0x84` | Сохранённые служебное значение и адрес кадров |
| `0x88` | Число кадров |
| `0x8c`, `0x90` | Первый и последний индекс, включительно |
| `0x94` | Частота кадров |
| `0x98` | Ticks на кадр |
| `0x9c` | Сохранённый интервал в миллисекундах |
| `0xa0` | Сохранённый адрес таблицы ID |
| `0xa4` | Число ID костей |
| `0xa8`, `0xac` | Два служебных поля, смысл пока не подтверждён |

Затем идут кадры: **32 байта заголовка**, за ними ключи. Заголовок кадра: `3 × f32` перемещения корня, индекс `u32`, старый адрес ключей `u32`, число ключей `u32`, два служебных `u32`.

Ключ: индекс кадра `u32`, ID кости `u32`, маска `u8`. Бит 0 добавляет четыре `f32` кватерниона **WXYZ**, бит 1 — три `f32` положения. Без каналов ключ занимает 9 байт, с обоими — 37. После всех кадров записана таблица ID: по одному `u32` на кость. Адреса сохранённого процесса пропускаются и никогда не используются как указатели.

Во всех 271 исследованных файлах кадры идут с нулевого индекса, каждый кадр содержит тот же набор ID, что и завершающая таблица. 270 клипов имеют 10 FPS, один — 30 FPS. Время воспроизведения рассчитывается по FPS: поле миллисекунд для 30 FPS округлено до 33. Последний кадр обозначает конец клипа: длительность `(число кадров − 1) / FPS`.

Парсер проверяет границы, счётчики, диапазоны кадров, ID, маски каналов, конечность координат и ненулевые кватернионы. Ограничения: файл до 512 МиБ, до 1 000 000 кадров, 16 384 костей и 2 000 000 ключей. Неизвестные биты каналов, остаток после таблицы и несогласованный набор костей возвращают ошибку.

## Воспроизведение в Bevy

Тело и голова используют одну проверяемую иерархию. Каждый узел становится сущностью с `Transform`, его родитель задаётся через `ChildOf`; meshes присоединяются к соответствующим узлам. Общий корень переводит Z-up SMF в Y-up Bevy и масштабирует персонажа для витрины. Bevy распространяет преобразования родителей на дочерние части.

`Clip` в `motion.rs` сопоставляет ключи по **ID**, а не по порядку узлов. Кватернион BMF переводится из WXYZ в XYZW, нормализуется и сопрягается: `(-x, −y, −z, w)`. Оригинальная функция `0x004A10A0` создаёт матрицу `R(q)` построчно, а преобразования игры используют векторы-строки. Для векторов-столбцов Bevy нужна транспонированная матрица `R(q)ᵀ`, то есть обратный единичный кватернион. Это проверено по коду матриц и на жесте рукой.

Для каждого кадра берутся базовые положения SMF. Найденный ключ задаёт абсолютный поворот узла; отсутствующий канал поворота в ключе означает единичный кватернион, как в загрузчике оригинала. Узел, которого нет среди ключей, сохраняет базовый `Transform`. Между соседними кадрами повороты интерполируются через `slerp`, положения — через `lerp`.

В исследованной функции `0x0049D520` положение ключа применяется только к тазу с **ID 1**, а узел **46 (Backpack)** пропускается. Это теперь повторено в `Clip`. Положения остальных костей BMF сохраняются парсером для исследования, но к скелету не присваиваются: там отличаются стороны и пропорции экспортированного скелета. Такой порядок сохраняет соединения рук и ног выбранного SMF.

Перемещение корня хранится отдельно от положения таза. Траектория отсчитывается от первого кадра. При переходе через конец клипа добавляется перемещение целого цикла, затем остаток нового: персонаж продолжает идти вперёд. Одно кадровое движение не имеет длительности и не делит время на ноль. Общий корень переводит перемещение из Z-up SMF в Y-up Bevy и использует тот же масштаб, что и геометрия.

`Playback` хранит фазу клипа и накопленное перемещение раздельно. Пауза останавливает оба; шаг по кадрам изменяет фазу и соответствующее перемещение. В режиме на месте фаза продолжается, а накопленная позиция сохраняется. При повторном включении движение продолжается от этой точки. Смена клипа сохраняет позицию и смешивает текущую позу с новым клипом за 0.25 секунды; начало движения также получает вес перехода. Это наше простое смешивание для витрины, точный алгоритм переходов старого EXE ещё не воспроизведён.

Проверяемые клипы: стояние — 1 кадр; `walk_rifle` — 13 кадров / 1.2 с; бег — 7 кадров / 0.6 с; жест — 41 кадр / 4 с. Все имеют 10 FPS. За цикл исходная траектория ходьбы проходит 180 единиц, бега — 400. У `walk_rifle` совпадают начальная и конечная позы; короткий `walk_80` заканчивается остановкой и подходит для отдельного шага, а не непрерывной ходьбы. АК-47 присоединён к правой кисти с ID 54 и следует за её анимацией. `--weapon none` включает прежний просмотр без оружия. Размер в окне нормализован по росту персонажа; показанные координаты — единицы витрины.

Это ещё не управление бойцом на карте. Поворот персонажа по направлению движения, навигация, столкновения, перенос разных скелетов, другие виды экипировки и точное сравнение движения/материалов с EXE требуют следующих этапов. Просмотрщик принимает дополнительный `--motion`, если его ID совместимы с выбранным телом; проверка всех 271 BMF как данных не означает проверки всех 271 клипов в движении.

Материалы используют обычное освещение Bevy. Загрузчик текстур учитывает `_ck`, RAW и собственный альфа-канал, как описано в [MATERIALS-RU.md](MATERIALS-RU.md). Цвета вершин и остальные оригинальные эффекты материалов ещё требуют реализации. Камера и масштаб служат просмотру; это ещё не игровая сцена.

## Изучение Rust

1. `shadow-formats/src/bmf.rs`: `Option` различает отсутствующий канал и записанное значение. Проследи, как маска меняет размер записи.
2. `shadow-tools/src/motions.rs`: итераторы проходят по кадрам и ключам. SHA-256 проверяет все декодированные каналы без огромного JSON вершин.
3. `shadow-model-viewer/src/rig.rs` собирает общую иерархию тела и головы. `motion.rs` связывает ID с узлами через `BTreeMap`, создаёт позы и рассчитывает дельту через стык цикла.
4. `shadow-model-viewer/src/character.rs`: компонент `Bone` хранит индекс; система `animate` записывает позу через `Query`. `move_root` применяет накопленное смещение; `orbit_camera` следует за ним. `Playback` — ресурс времени, перехода, паузы и позиции.

Упражнение: поменяй длительность перехода `BLEND_SECONDS` и наблюдай переключение W/S. Затем добавь четвёртую скорость 0.25×. Проследи, почему `seconds` сбрасывается при смене клипа, а `travel` сохраняется. Геометрию и бинарный парсер для этого менять не нужно.

```bash
cargo run --locked -p shadow-tools -- motions --game-dir "/путь/к/игре" --json
cargo run --locked -p shadow-tools -- motion --game-dir "/путь/к/игре" \
  --asset motions/bipedal_stand_wave.bmf --json

# Детерминированный кадр: фиксированное время, PNG и автоматическое завершение.
cargo run --locked -p shadow-model-viewer --bin shadow-character-viewer -- \
  --game-dir "/путь/к/игре" --motion motions/bipedal_stand_wave.bmf \
  --pose-time 2.0 --screenshot peter.png
```


Для независимой проверки позы без открытия окна можно выгрузить JSON. Он содержит локальные преобразования всех узлов, исходное положение корня и перемещение в координатах Bevy:

```bash
cargo run --locked -p shadow-model-viewer --bin shadow-character-viewer -- \
  --game-dir "/путь/к/игре" --pose-time 0.3 --pose-json walk-pose.json
```

## Крепление оружия

Исходный профиль АК-47 ссылается на `AlItGn-AK47j` и `EQL_RIGHT_HAND`. Функция оригинала `0x0040C640` сопоставляет правую руку с ID 54; вызов `0x0049A0C0` присоединяет корень модели оружия к этому узлу через `0x00493130`. В Bevy meshes оружия становятся дочерними частями кисти. Их локальные преобразования SMF сохраняются; отдельное нормирование размера винтовки не применяется.

Семь значений `OBJECT_RENDER_DATA` задают матрицу отдельного отображения предмета, поэтому для крепления к кисти не используются. Узел `Skell-BS` с ID 12 не выбран точкой крепления. Модель АК-47 содержит 54 вершины и 75 треугольников; с персонажем получается 410 вершин и 487 треугольников.

JSON позы дополнительно содержит путь оружия, ID кисти, перенос начала витрины и координаты вершин оружия в мире. Это позволяет проверить преобразование независимо от кадра. Стояние, бег и жест в прототипе сохраняют выбранное оружие; полноценная система экипировки и подбор специализированных вооружённых клипов ещё предстоят.

## Применение к новым стойкам — 14 октября 2026

Для стойки без явного положения таза применяется исходный `DEFAULT_COG_POSITION`. Отсутствующий в SMF узел BMF пропускается, как в оригинальном `0x0049D629`: исходные crouch/prone-aim содержат необязательные ID 81–83. Ранее просмотрщик отклонял такие клипы; это ограничение снято. Неверная структура, маски и нечисловые ключи по-прежнему отклоняются парсером. [Сверка и новые стойки](SMG-RU.md).
